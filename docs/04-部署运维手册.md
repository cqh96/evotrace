## 2. 快速启动（本地开发）

### 2.1 启动依赖中间件

```bash
docker compose -f deploy/docker-compose.yml up -d
```

启动的服务：

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| PostgreSQL 16 + pgvector | 5432 | 业务数据 + 向量检索 |
| Kafka | 9092 | 事件总线 |
| Redis | 6379 | 缓存/限流 |
| MinIO | 9000/9001 | 对象存储 |
| Neo4j | 7474/7687 | 演化图谱 |
| Elasticsearch | 9200 | 全文检索 |

### 2.2 构建

```bash
mvn -T 1C clean install -DskipTests
```

### 2.3 启动服务端

```bash
mvn -pl evotrace-server spring-boot:run
```

Flyway 自动执行数据库迁移（V1-V4），服务监听 `http://localhost:8080`。

### 2.4 启动前端

```bash
cd evotrace-ui && npx vite
```

前端监听 `http://localhost:5173`，API 请求代理到 `:8080`。

### 2.5 验证

```bash
# 健康检查
curl http://localhost:8080/actuator/health

# 登录
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

浏览器打开 `http://localhost:5173`，使用 `admin / admin123` 登录。

## 3. 配置说明

### 3.1 服务端配置 (`application.yml`)

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/evotrace
    username: evotrace
    password: evotrace
  kafka:
    bootstrap-servers: localhost:9092
  ai:
    openai:
      base-url: ${AI_BASE_URL:https://api.openai.com}
      api-key: ${AI_API_KEY:sk-placeholder}
      chat.options.model: ${AI_CHAT_MODEL:gpt-4o-mini}

evotrace:
  ingestion:
    max-inline-diff-bytes: 262144     # 256KB
  snapshot:
    full-baseline-interval: 20        # 每20个版本全量基线
  ai:
    privacy-default: STRUCTURE_ONLY   # FULL_CODE / STRUCTURE_ONLY / LOCAL_ONLY
  jwt:
    secret: <生产环境必须修改>
    ttl-hours: 12
```

### 3.2 AI 模型配置

支持 OpenAI 兼容协议。切换到其他模型提供方：

```yaml
# 火山方舟
spring.ai.openai.base-url: https://ark.cn-beijing.volces.com/api/v3
spring.ai.openai.api-key: ${ARK_API_KEY}

# Ollama 本地模型
spring.ai.openai.base-url: http://localhost:11434
spring.ai.openai.api-key: ollama
spring.ai.openai.chat.options.model: qwen2.5:7b
```

### 3.3 隐私模式

| 模式 | 说明 |
| --- | --- |
| `FULL_CODE` | 原始代码全文发送到 AI 模型（云端） |
| `STRUCTURE_ONLY` | 仅发送结构化摘要（接口指纹、依赖清单等） |
| `LOCAL_ONLY` | 强制路由到 Ollama 本地模型，代码不出内网 |

项目级配置：创建/更新项目时设置 `privacy_level`。

## 4. 数据库迁移

### 4.1 迁移版本

| 版本 | 文件 | 内容 |
| --- | --- | --- |
| V1 | `V1__init.sql` | 核心表：workspace/project/change_event/snapshot/ai |
| V2 | `V2__iam.sql` | 用户表：sys_user |
| V3 | `V3__analysis.sql` | 分析引擎：依赖图/订阅/破坏性变更/风险评分/通知日志 |
| V4 | `V4__pm_qa.sql` | PM/QA全链路：需求/测试用例/测试执行/缺陷/质量门禁/端到端追溯 |

### 4.2 手动迁移

```bash
# 查看迁移状态
docker exec deploy-postgres-1 psql -U evotrace -d evotrace \
  -c "SELECT version, description, script, installed_on FROM flyway_schema_history;"

# 修复失败的迁移
docker exec deploy-postgres-1 psql -U evotrace -d evotrace \
  -c "DELETE FROM flyway_schema_history WHERE success = false;"
```

### 4.3 重置序列

当 Seeder 使用 `OVERRIDING SYSTEM VALUE` 手动插入 ID 后：

```bash
docker exec deploy-postgres-1 psql -U evotrace -d evotrace <<EOF
SELECT setval('workspace_id_seq', (SELECT max(id) FROM workspace));
SELECT setval('project_id_seq', (SELECT max(id) FROM project));
SELECT setval('application_id_seq', (SELECT max(id) FROM application));
SELECT setval('sys_user_id_seq', (SELECT max(id) FROM sys_user));
EOF
```

## 5. Kafka 运维

### 5.1 Topic 管理

```bash
# 查看 topic
docker exec deploy-kafka-1 /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --list

# 查看消费组
docker exec deploy-kafka-1 /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --list
```

### 5.2 重置消费偏移

```bash
# 卡在旧消息时，跳转到最新
docker exec deploy-kafka-1 /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --group change-service \
  --topic evo.events.raw \
  --reset-offsets --to-latest --execute
```

### 5.3 Topic 结构

| Topic | 消费者 | 分区键 |
| --- | --- | --- |
| `evo.events.raw` | change-service | projectKey |
| `evo.tasks.ai` | ai-analysis | eventId |

## 6. 生产环境建议

### 6.1 JVM 参数

```bash
java -jar evotrace-server.jar \
  -XX:+UseZGC \
  -XX:+ZGenerational \
  --enable-preview \
  -Dspring.threads.virtual.enabled=true
```

### 6.2 环境变量

```bash
export AI_BASE_URL=https://your-ai-endpoint
export AI_API_KEY=sk-xxx
export AI_CHAT_MODEL=gpt-4o
export EVOTRACE_JWT_SECRET=<32+字节随机字符串>
```

### 6.3 健康检查

```bash
# Kubernetes probes
livenessProbe:  GET /actuator/health/liveness
readinessProbe: GET /actuator/health/readiness

# Prometheus metrics
GET /actuator/prometheus
```

### 6.4 日志

```yaml
logging:

    io.evotrace: INFO
    org.springframework.kafka: WARN
  pattern:
    file: '{"time":"%d","level":"%p","traceId":"%X{traceId}","msg":"%m"}%n'
```

## 7. 故障排查

| 症状 | 检查 | 解决方案 |
| --- | --- | --- |
| 项目创建失败 500 | PostgreSQL 序列冲突 | 执行序列重置（§4.3） |
| Kafka 反序列化异常 | 旧消息格式不匹配 | 重置消费偏移（§5.2） |
| AI 摘要显示 PENDING | API Key 未配置或额度不足 | 检查 AI 模型配置（§3.2） |
| Map.of() NPE | 数据库查询返回 null | 检查对应接口是否传入有效参数 |
| 前端代理失败 | Vite 未启动 | `cd evotrace-ui && npx vite` |
