## 1. 三步接入

```
创建项目 → 拿凭证 → 推送事件(签名) → 页面查看时间线/AI摘要/问答
```

**① 创建项目**（自动生成 `apiKey` + `apiSecret`，仅此一次明文展示）：

```bash
curl -X POST $SERVER/api/v1/projects \
  -H "Authorization: Bearer <JWT>" -H 'Content-Type: application/json' \
  -d '{"projectKey":"pay-platform","name":"支付平台","repoUrl":"https://github.com/x/pay.git"}'
# → { apiKey: "evo_xxx", apiSecret: "hex64" }
```

**② 推送事件**（HMAC-SHA256 签名，**必须对原始请求体原样签名**）：

```bash
BODY='{"protocolVersion":"v1","eventId":"e-001","projectKey":"pay-platform","appKey":"payment-service","eventType":"CODE_COMMIT","occurredAt":"2026-08-02T14:10:00+08:00","source":"GITLAB_WEBHOOK","idempotencyKey":"gitlab:pay-platform:push:abc","payload":{"branch":"main","commitSha":"abc","authorName":"wangwu","message":"feat: xxx","files":[]},"blobRef":null}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$API_SECRET" | awk '{print $2}')
curl -X POST $SERVER/open-api/v1/events -H "X-EvoTrace-Api-Key: $API_KEY" \
  -H "X-EvoTrace-Signature: $SIG" -H 'Content-Type: application/json' -d "$BODY"
# → { success: true, data: { eventId, duplicated: false } }
```

**③ 验证**：页面时间线出现事件 → 数十秒后 AI 摘要 DONE → 演化问答可检索提问。

## 2. 事件协议速查

**请求体 (Envelope v1)**：

```json
{
  "protocolVersion": "v1",
  "eventId": "唯一事件ID",
  "projectKey": "项目标识",
  "appKey": "应用标识",
  "eventType": "CODE_COMMIT",
  "occurredAt": "2026-08-02T14:30:00+08:00",
  "source": "GITLAB_WEBHOOK",
  "idempotencyKey": "业务唯一键,重复推送自动去重",
  "payload": { "事件类型对应的载荷" },
  "blobRef": null
}
```

| eventType | 载荷要点 |
| --- | --- |
| `CODE_COMMIT` | branch / commitSha / authorName / message / files[] |
| `MR_MERGED` | 同 CODE_COMMIT |
| `RELEASE_TAG` | tag / commitSha / message |
| `INVENTORY_REPORT` | 依赖/配置/API 清单 |
| `CONFIG_CHANGE` | configCenter / keys[] / description |
| `DDL_CHANGE` | database / ddl / description |
| `DEPLOY_RECORD` | 部署记录 |

**约束**：
- `source` **必须是枚举**：`CLI / GITLAB_WEBHOOK / GITHUB_WEBHOOK / GITEE_WEBHOOK / OPEN_API / JAVA_SDK / FEISHU / JIRA`（自定义值报 500）
- 大 diff（>256KB）先 `POST /open-api/v1/blobs` 拿 `blobRef` 再引用
- 重复推送同 `idempotencyKey` 自动去重（`duplicated: true`）

## 3. 三对接方式对比

| 方式 | 适用场景 | 入口 |
| --- | --- | --- |
| **GitLab/GitHub Webhook** | 仓库事件全自动 | 仓库 Settings → Webhooks → `$SERVER/open-api/v1/webhooks/gitlab`(或 `/github`),无需签名。GitLab 若配置 `GITLAB_TOKEN`，push 会自动拉 commit diff 入库 |
| **开放 REST API** | 任意系统/CI 脚本 | `$SERVER/open-api/v1/events`(签名见 §1) |
| **Java SDK Starter** | Spring Boot 应用 | 引入 `evotrace-sdk-java`,自动上报依赖/配置/API 清单 |

## 3.5 飞书多维表格(Bitable) 双向同步

> 公司不用 Jira、用飞书多维表格记录测试用例与缺陷时，可让 EvoTrace 与飞书多维表格**双向同步**：缺陷 + 测试用例，定时拉取 + 本地新建/流转自动回写。与 Jira 并存，按项目独立启用。

**前提**：
1. 在 [飞书开放平台](https://open.feishu.cn) 创建**自建应用**，获取 `App ID` / `App Secret`
2. 给应用开通权限：`bitable:app:readonly`（读取）、`bitable:record`（写入记录）
3. 把该应用加入你要同步的多维表格的**可编辑协作者**

**配置入口**：QA 工作台 → 右上角「飞书表格同步」弹窗

| 配置项 | 说明 |
| --- | --- |
| App ID / App Secret | 自建应用凭证（Secret 只写，不回显） |
| Bitable Token | 多维表格的 `app_token`（开放平台/链接中的 app token，**不是** wiki 节点 token） |
| 缺陷表 ID | 缺陷所在表格 `table_id`，如 `tblTcvWwJyfjyWpb`；留空则不同步缺陷 |
| 用例表 ID | 用例所在表格 `table_id`；留空则不同步用例 |
| 字段映射 | 每行 `EVO字段=飞书列名`。EVO字段：`title/description/severity/status/testType/priority/steps`；列名与字段同名时保持默认 |
| 状态映射 | 每行 `EVO状态=飞书列值`，如 `OPEN=待处理`、`IN_PROGRESS=处理中` |

**同步行为**：
- **拉取**（飞书 → EvoTrace）：定时（默认每日 00:40，可配 `evotrace.feishu.pull-cron`）+ 弹窗「手动同步」。按 `record_id` 去重 upsert，`source='FEISHU'`，`external_key=record_id`
- **回写**（EvoTrace → 飞书）：本地新建缺陷/用例自动在飞书建行；缺陷状态流转自动更新飞书对应行
- **降级**：未配置 / 未启用 / 飞书不可达 → 仅记日志跳过，绝不阻塞本地流程

**接口**：
```
GET  /api/v1/projects/{projectKey}/feishu/config   # 读取配置
PUT  /api/v1/projects/{projectKey}/feishu/config   # 保存配置
POST /api/v1/projects/{projectKey}/feishu/sync     # 手动拉取 → { bugs, cases }
```

## 4. 常见错误排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 401 | API Key 错 / 签名错 | 签名必须对**原始请求体**计算;凭证过期需页面「轮换」 |
| 500 + `Enum` 相关 | `source` 非枚举值 | 改用枚举值(见 §2) |
| 500 + 其他 | payload 字段不符 | 对照事件类型载荷 |
| 摘要 `FAILED` | AI 调用失败(超时/限流) | 检查 AI 模型配置的 Key 与额度;等待自动重试 |
| 摘要 `PENDING` 长期不变 | 模型未配置 Key | 「AI 模型配置」页配置并测试连接 |
| 问答检索不到 | 事件无摘要(非 CODE_COMMIT 事件当前不生成摘要) | 推送 CODE_COMMIT 事件;或补充 DDL/CONFIG 摘要能力 |

## 5. 完整对接示例（Python）

```python
import hmac, hashlib, json, urllib.request

SERVER, API_KEY, API_SECRET = "http://43.155.130.69", "evo_xxx", "hex64"

def push_event(ev):
    body = json.dumps({"protocolVersion": "v1", "projectKey": "pay-platform",
                       "appKey": "payment-service", "blobRef": None, **ev},
                      ensure_ascii=False).encode()
    sig = hmac.new(API_SECRET.encode(), body, hashlib.sha256).hexdigest()
    req = urllib.request.Request(f"{SERVER}/open-api/v1/events", data=body,
        headers={"Content-Type": "application/json",
                 "X-EvoTrace-Api-Key": API_KEY, "X-EvoTrace-Signature": sig})
    return json.loads(urllib.request.urlopen(req).read())

push_event({"eventId": "e-001", "eventType": "CODE_COMMIT",
            "occurredAt": "2026-08-02T14:10:00+08:00", "source": "GITLAB_WEBHOOK",
            "idempotencyKey": "gitlab:pay-platform:push:abc",
            "payload": {"branch": "main", "commitSha": "abc", "authorName": "wangwu",
                        "message": "feat: xxx", "files": []}})
```

## 6. CI/CD 集成（Jenkins / GitHub Actions）

EvoTrace 提供 **Webhook 触发**能力，让测试计划进入 DevOps 流水线，实现"提交即测试、质量门禁卡发布"。

### 6.1 触发方式

| 方式 | 说明 | 适用场景 |
| --- | --- | --- |
| **Webhook（推荐）** | `POST /api/v1/ci/run`，携带 `X-CI-Token` 鉴权 | Jenkins / GitLab CI / GitHub Actions / 任意脚本 |
| 定时 Cron | 在「CI 集成」页绑定计划 + cron，服务端轮询触发 | 每日回归、夜间构建 |
| MR 触发 | 配置触发类型 `MR`，结合订阅/Webhook 事件联动 | 合并请求门禁 |

### 6.2 Jenkinsfile 示例

```groovy
// Jenkinsfile
pipeline {
  agent any
  environment {
    EVOTRACE_TOKEN = credentials('evotrace-ci-token')   // 在 Jenkins 凭据中配置
    EVOTRACE_URL   = 'http://43.155.130.69'            // EvoTrace 服务地址
  }
  stages {
    stage('触发 EvoTrace 测试') {
      steps {
        sh """curl -f -X POST "\${EVOTRACE_URL}/api/v1/ci/run" \\
          -H "Content-Type: application/json" \\
          -H "X-CI-Token: \${EVOTRACE_TOKEN}" \\
          -d '{
            "projectKey": "pay-platform",
            "planId": 3,
            "generateReport": true
          }'"""
      }
    }
  }
}
```

### 6.3 GitHub Actions 示例

```yaml
# .github/workflows/test-gate.yml
name: Test Gate
on: [push, pull_request]
jobs:
  evotrace:
    runs-on: ubuntu-latest
    steps:
      - name: Trigger EvoTrace test plan
        run: |
          curl -f -X POST "${{ secrets.EVOTRACE_URL }}/api/v1/ci/run" \
            -H "Content-Type: application/json" \
            -H "X-CI-Token: ${{ secrets.EVOTRACE_TOKEN }}" \
            -d '{"projectKey":"pay-platform","planId":3,"generateReport":true}'
```

### 6.4 关键点

- **Token 鉴权**：请求头 `X-CI-Token`，默认值 `evotrace-devops-2026`，生产环境请在服务端以 `evotrace.ci.token` 覆盖，并妥善保管。
- **返回结构**：成功返回 `{ planId, planName, total, runnable, skipped, passed, failed, durationMs, report? }`，可用 `passed/failed` 做质量门禁判断。
- **报告落库**：`generateReport: true` 时自动生成可视化报告，可在「测试报告」页查看并用分享链接对外公开。
- **角色**：先到「CI 集成」页创建触发配置（绑定某个测试计划），再把对应 `planId` 填入流水线。

### 6.5 质量门禁建议

```sh
# 流水线中判断：失败率 > 0 则中断发布
resp=$(curl -s -X POST ... "$EVOTRACE_URL/api/v1/ci/run" ...)
failed=$(echo "$resp" | jq -r '.data.failed')
if [ "$failed" -gt 0 ]; then echo "质量门禁未通过"; exit 1; fi
```
