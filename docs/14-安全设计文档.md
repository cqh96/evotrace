## 1. 安全目标

EvoTrace 作为覆盖「需求 → 代码 → 测试 → 缺陷 → 发布」全链路的研发协作平台，承载代码变更、需求、缺陷、第三方集成凭证等敏感数据。安全设计围绕以下目标展开：

1. **身份可信**：仅合法用户可登录控制台，仅合法客户端可上报数据。
2. **数据保密**：凭证类数据不被泄露或回显，传输链路加密。
3. **权限可控**：按系统角色与项目角色做功能与数据隔离。
4. **可审计**：关键操作留有记录，错误码可定位。
5. **默认安全**：默认配置尽量安全，减少误用风险。

## 2. 安全架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                        客户端 / 插件                          │
│   evotrace-sdk-java · CLI · VS Code/IDEA · Git Webhook      │
└──────────────────────────────┬──────────────────────────────┘
                               │ HMAC-SHA256 签名（X-EvoTrace-Api-Key）
                               │ + X-EvoTrace-Signature
┌──────────────────────────────▼──────────────────────────────┐
│                        Open API（事件上报）                    │
│   /open-api/v1/*  ====  SignatureVerifier 校验签名            │
│   RawBodyCaptureFilter 捕获原始字节                            │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                     Control Plane（控制台）                    │
│   /api/v1/*  ====  JwtAuthFilter 校验 Bearer JWT             │
│   SecurityConfig 统一鉴权 · BCrypt 密码校验                    │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                     AI 服务 / 三方集成                         │
│   OpenAI etc.（ai_model_config）· Jira · Feishu · MinIO       │
└─────────────────────────────────────────────────────────────┘
```

两类安全边界：

- **Open API 边界**：面向外部系统（SDK/CLI/Webhook），采用 **API Key + HMAC-SHA256 签名** 认证。
- **控制台边界**：面向登录用户，采用 **JWT（Bearer）** 认证，密码 BCrypt 哈希存储。

## 3. 认证（Authentication）

### 3.1 控制台登录（JWT + BCrypt）

| 项 | 说明 |
| --- | --- |
| 登录端点 | `POST /api/v1/auth/login` |
| 请求体 | `{ username, password }` |
| 密码校验 | `BCryptPasswordEncoder.matches()`，字段 `sys_user.password_hash`（VARCHAR 128） |
| 签发算法 | HMAC-SHA256（`Keys.hmacShaKeyFor`，jjwt 0.12.6） |
| Token 结构 | `{ sub: username, role: "ADMIN"|"USER", iat, exp }` |
| 过期时间 | `evotrace.jwt.ttl-hours`，默认 **12 小时** |
| 密钥来源 | `evotrace.jwt.secret` |
| 错误码 | `EVO-AUTH-100`（用户名或密码错误） |

**认证过滤器** `JwtAuthFilter`：从 `Authorization: Bearer <token>` 提取 token，解析成功后构造 `UsernamePasswordAuthenticationToken`（含 `ROLE_USER`）注入 `SecurityContextHolder`；解析异常则清空上下文。

### 3.2 Open API 凭证（API Key + HMAC 签名）

| 项 | 说明 |
| --- | --- |
| 凭证表 | `api_credential` |
| API Key | `api_key`，格式 `evo_<32 hex>`（唯一） |
| Secret | `hmac_key`（VARCHAR 128，明文用于签名校验） |
| Secret 哈希 | `secret_hash`（BCrypt，用于管理端校验展示） |
| 签名算法 | `HmacSHA256`，`SignatureVerifier` |
| 比较方式 | `MessageDigest.isEqual` 常量时间比较，防时序攻击 |
| 头部 | `X-EvoTrace-Api-Key` + `X-EvoTrace-Signature` |

**签名流程**（`IngestionService.validate`）：

1. 按 `apiKey` 查询凭证，校验 `status = ACTIVE`。
2. 校验项目 `status = ACTIVE`、`hmac_key` 非空。
3. 校验 `rawBody` 与 `signature` 非空。
4. `SignatureVerifier.verify(rawBody, hmacKey, signature)` 校验签名。

**原始字节捕获**：`RawBodyCaptureFilter` 仅对 `/open-api/*` 生效，在反序列化前捕获原始请求体并包装为可复用请求，确保签名基于原始字节计算。

**凭证生命周期**（`CredentialService`）：`rotate()` 吊销全部 ACTIVE 凭证并重新签发；`revoke()` 置为 REVOKED。生成使用 `SecureRandom`（16 字节 key + 24 字节 secret）。

### 3.3 CI 集成认证

| 项 | 说明 |
| --- | --- |
| 端点 | `POST /api/v1/ci/run` |
| 认证 | `X-CI-Token` 请求头 |
| 配置 | `evotrace.ci.token`，默认 `evotrace-devops-2026` |

> ⚠️ 该端点在 `SecurityConfig` 中 `permitAll()`，认证完全依赖静态 token。**生产环境务必修改默认值**。

## 4. 授权（Authorization）

### 4.1 系统角色

`sys_user.role` 当前仅定义 `ADMIN`（默认）。JWT 携带 `role` claim，但 `JwtAuthFilter` 当前硬编码 `ROLE_USER`，未使用 role 做强校验。

### 4.2 项目成员角色

`project_member.role` 取值：`ADMIN` / `PM` / `DEVELOPER` / `QA` / `OPS`。

| 端点 | 说明 |
| --- | --- |
| `GET /api/v1/projects/{key}/members` | 列出项目成员 |
| `POST .../members` | 添加成员（userId + role） |
| `DELETE .../members/{memberId}` | 移除成员 |
| `GET .../members/me` | 查询当前用户角色（未配置默认 `ADMIN`） |

> ⚠️ **当前限制**：项目成员角色**仅用于前端菜单与数据过滤**，后端未做基于角色的接口拦截。属高优先级改进项（见 §8）。

### 4.3 鉴权放行路径

`SecurityConfig` 公开路径（无需认证）：

```
/api/v1/auth/**      # 登录
/open-api/**         # 事件上报（由签名校验保护）
/actuator/health     # 健康检查
/api/v1/ci/run       # CI 集成（由 X-CI-Token 保护）
```

其余所有路径 `anyRequest().authenticated()`；未认证返回 `{ success:false, code:"EVO-AUTH-401", message:"未登录或登录已过期" }`。

## 5. 传输安全

| 项 | 说明 |
| --- | --- |
| 会话 | `SessionCreationPolicy.STATELESS`（无状态） |
| CSRF | `csrf.disable()`（无状态 + JWT 场景合理） |
| HTTPS | 生产环境由反向代理（Nginx 等）终止 TLS，见 04-部署运维手册 |
| CORS | 当前未配置全局 CORS；若前后端跨域需在网关层补充 |

## 6. 数据安全

### 6.1 密码与凭证存储

| 数据 | 存储方式 | 风险 |
| --- | --- | --- |
| 用户密码 | BCrypt 哈希（`password_hash`） | 🟢 低 |
| Open API Secret | `hmac_key` 明文 + `secret_hash` BCrypt | 🟡 明文仅签名用，需权限保护 |
| AI 模型 API Key | `ai_model_config.api_key` **明文**（列表脱敏 `sk-****2345`） | 🔴 高，建议加密 |
| Jira 凭证 | `project_jira_config.api_token` **明文**（存取时 `remove("apiToken")` 不回显） | 🔴 高，建议加密 |
| 飞书凭证 | `project_feishu_config.app_secret` **明文**（不回显） | 🔴 高，建议加密 |

### 6.2 SDK 配置脱敏

`ConfigInventoryCollector` 默认敏感 key 正则 `(?i).*(password|secret|token|key).*`，匹配的配置值使用 SHA-256 哈希后上报，不上传明文。

### 6.3 对象存储访问控制

当前 Blob 存储为内存 + 本地文件系统（`evotrace.blob.dir`，默认 `./data/blobs`），通过 blobRef（UUID）访问，**无认证**。MinIO 迁移为 TODO。生产环境建议：

- 接入 MinIO 并为 bucket 设置私有访问策略；
- 生成带过期时间的预签名 URL 供下载；
- 对 blobRef 增加访问鉴权。

## 7. 审计与错误码

### 7.1 全局异常处理

`GlobalExceptionHandler`：

| 异常 | HTTP | 错误码 |
| --- | --- | --- |
| `IllegalArgumentException` | 400 | `EVO-BIZ-400` |
| `EmptyResultDataAccessException` | 404 | `EVO-BIZ-404` |
| `Exception` | 500 | `EVO-SYS-500`（日志记录 unhandled error） |

### 7.2 统一错误码（`ErrorCodes`）

| 错误码 | 含义 |
| --- | --- |
| `EVO-AUTH-001` | 签名无效 |
| `EVO-AUTH-002` | 凭证过期 |
| `EVO-AUTH-100` | 用户名或密码错误 |
| `EVO-AUTH-401` | 未登录或登录已过期 |
| `EVO-INGEST-001` | 重复事件 |
| `EVO-INGEST-002` | 载荷过大 |
| `EVO-BIZ-001` | 项目不存在/已停用 |
| `EVO-AI-001` | AI 配额超限 |
| `EVO-SYS-500` | 服务内部错误 |

## 8. 安全风险清单与改进建议

| 优先级 | 风险 | 现状 | 建议 |
| --- | --- | --- | --- |
| P0 | 后端权限校验缺失 | 无 `@PreAuthorize`，角色仅前端过滤 | 引入方法级鉴权，按项目成员角色校验接口 |
| P0 | Webhook 无独立 secret 校验 | GitHub `X-Hub-Signature-256` 未实现，`X-EvoTrace-Api-Key` 可选 | 实现 webhook secret 签名校验 |
| P0 | AI/三方凭证明文入库 | `api_key`/`api_token`/`app_secret` 明文 | 引入可逆加密（如 AES-GCM + 密钥管理） |
| P1 | JWT 默认 secret 过弱 | 默认 `evotrace-dev-secret-key-please-override-*` | 强制生产环境覆盖，配置长度 ≥ 32 字节 |
| P1 | 无限流 | 所有端点无速率限制 | 引入限流（登录、Open API 上报）防暴力破解/刷量 |
| P1 | CI token 默认值已知 | 默认 `evotrace-devops-2026` | 生产环境必改，纳入配置校验 |
| P2 | Blob 无访问控制 | 本地文件 + UUID | 接入 MinIO 私有桶 + 预签名 URL |
| P2 | CORS 未配置 | 无全局 CORS | 网关层按白名单配置 CORS |
| P2 | 登录无失败锁定 | 无次数限制 | 增加登录失败锁定与验证码 |

## 9. 安全配置清单（生产检查项）

部署前请逐项核对（详见 04-部署运维手册.md）：

- [ ] `evotrace.jwt.secret` 已覆盖为强随机值（≥ 32 字节）。
- [ ] `evotrace.ci.token` 已覆盖非默认值。
- [ ] 默认管理员 `admin/admin123` 已修改并禁用无关账号。
- [ ] `spring.ai.openai.api-key` 与各 `ai_model_config.api_key` 通过安全渠道注入（环境变量/密钥管理）。
- [ ] 数据库连接使用最小权限账号，不使用超级用户。
- [ ] 生产环境开启 HTTPS，关闭非必要端口。
- [ ] Kafka 若启用认证，配置 SASL 与 ACL。
- [ ] 对象存储接入 MinIO 并配置私有策略。
