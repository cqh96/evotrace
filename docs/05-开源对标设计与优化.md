# EvoTrace 开源对标借鉴与优化设计文档

> 版本：v0.1（草案）
> 范围：基于对 GitHub / Gitee 开源项目的调研，借鉴其设计与可移植功能，优化 EvoTrace 现有四大模块。
> 原则：小步增量、不破坏现有数据模型、优先可独立交付的功能点。

---

## 0. 调研结论摘要

经核实，以下开源项目真实存在且与 EvoTrace 功能高度对应，可作为借鉴对象：

| 借鉴方向 | 对标开源项目 | 平台 | 核心可借鉴点 |
|---------|------------|------|------------|
| AI 代码审查 / 变更摘要 | **PR-Agent** (Qodo/The-PR-Agent) | GitHub ~12k⭐ | 多工具分工(/review /describe /improve /ask)、PR 描述生成、审结果回写 Git 平台、多模型路由 |
| 测试链路 | **MeterSphere** (飞致云) | Gitee/GitCode | 测试用例↔需求↔缺陷关联、AI 生成用例、计划编排 |
| 代码质量门禁 | **SonarQube CE** / ArchUnit | GitHub ~10k⭐ | 质量门禁可配置化、复杂度/重复度检查 |
| 需求/迭代管理 | **禅道 ZenTao** | Gitee | 需求状态历史审计、迭代看板/燃尽图 |
| AI 模型配置 | **Ollama** + LangChain4j | GitHub | 本地模型接入、多模型路由策略 |

> 注：CodeRabbit 已转向商业产品，开源参考价值有限，故主推 PR-Agent。

## 1. 方向一：AI 审查增强（对标 PR-Agent）

### 1.1 现状分析

- [CodeReviewEngine.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/ai/CodeReviewEngine.java) 已具备：AI 生成代码检测、diff 审查、结构化发现项。
- 局限：
  1. **无单 MR/PR 描述生成**。[ReleaseNotesService.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/ai/ReleaseNotesService.java) 只做版本级发布说明。
  2. **审查结果不推回 Git 平台**。`review()` 只落库到 `ai_code_review` / `review_finding`，不写回 GitLab/GitHub PR。
  3. **审查模板不可按项目/工作区定制**。Prompt 硬编码在 `buildReviewPrompt()`。
  4. **diff 截断无分块策略**。`buildDiffContext()` 超出 `maxDiffChars` 直接截断，大 PR 信息丢失。

### 1.2 借鉴设计方案

**(a) 单 MR 描述生成器 `PrDescriptionGenerator`**
- 新增 service，输入 `eventId`（或 MR id），输出 PR 标题 + 描述（markdown）。
- 复用 `PromptLoader` + `CodeReviewEngine.buildDiffContext()` 的 diff 上下文。
- 新增 prompt 模板 `pr-description.st`。
- 产出落库到 `ai_semantic_unit`（kind=`PR_DESCRIPTION`），供前端 PR 明细展示。

**(b) 审查结果回写 Git 平台 `CodeReviewPushbackService`**
- 读取 `review_finding`，调用 GitLab/GitHub API 创建 PR 审查评论 / 行内评论。
- 对接现有 `CredentialController` / `WebhookController` 的凭据管理。
- 幂等：按 `review_id` 记录已回写状态，避免重复评论。
- 新增接口：`POST /code-review/{eventId}/push-back`。

**(c) 审查模板可配置化**
- 在 project/workspace 级别增加 "review instructions" 配置字段。
- `buildReviewPrompt()` 拼接用户自定义指令段。
- 借鉴 PR-Agent 的 JSON 规则配置，允许增删审查分类。

**(d) diff 分块策略**
- 借鉴 PR-Agent 的 PR compression：按文件分块，超长文件先摘要再分批审查。
- 控制 token 成本，保持审查覆盖度。

### 1.3 改动清单

| 类型 | 文件/模块 | 改动 |
|------|----------|------|
| 新增 | `server/ai/PrDescriptionGenerator.java` | 单 MR 描述生成 |
| 新增 | `server/ai/CodeReviewPushbackService.java` | 回写 Git 平台 |
| 新增 | `evotrace-ai-prompts/pr-description.st` | PR 描述模板 |
| 修改 | `server/ai/CodeReviewController.java` | 新增 2 个端点 |
| 修改 | `server/ai/CodeReviewEngine.buildDiffContext()` | 分块策略 |
| 修改 | `server/ai/CodeReviewEngine.buildReviewPrompt()` | 支持自定义指令 |
| 数据库 | 新 migration | review 回写状态字段 / 项目审查配置字段 |

## 2. 方向二：测试链路增强（对标 MeterSphere）

### 2.1 现状分析

- [TestRecommendationEngine.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/testing/TestRecommendationEngine.java) 已能按变更文件/API 推荐测试用例、生成回归范围。
- 局限：
  1. **测试用例与需求/缺陷关联弱**。`related_files ILIKE` 模糊匹配，无结构化关联。
  2. **无 AI 生成测试用例能力**。只能推荐已有用例。
  3. **无拖拽式测试计划编排**（对照 MeterSphere 计划编排）。

### 2.2 借鉴设计方案

**(a) 测试用例↔需求↔缺陷 结构化关联**
- 复用现有 `test_case.requirement_id`、`bug_ticket.requirement_id` 字段补齐索引与 API。
- 在 `QaController` 增加 "需求追溯矩阵" 接口：输入需求 → 返回关联用例、执行状态、关联缺陷。
- `TestRecommendationEngine` 升级：优先按 `requirement_id` 精确匹配，文件匹配作为兜底。

**(b) AI 测试用例生成 `AiTestCaseGenerator`**
- 输入变更文件/diff + 需求，调用模型生成 JUnit/接口测试用例建议（markdown + 可执行断言）。
- 复用 `ModelRouter.clientFor("TEST_GENERATION")`。
- 新增 prompt 模板 `test-case-generation.st`。
- 产出可作为建议展示，不自动写入 `test_case`（避免污染数据）。

**(c) 测试计划编排增强**
- 前端在 [QADashboardView.vue](file:///Users/sheeran/gee/evotrace/evotrace-ui/src/views/QADashboardView.vue) 增加用例拖拽添加/排序（轻量实现，不引入重型 DnD 库）。

### 2.3 改动清单

| 类型 | 文件/模块 | 改动 |
|------|----------|------|
| 新增 | `server/testing/AiTestCaseGenerator.java` | AI 生成用例建议 |
| 新增 | `evotrace-ai-prompts/test-case-generation.st` | 用例生成模板 |
| 修改 | `server/testing/TestRecommendationEngine.java` | 结构化关联优先 |
| 修改 | `server/qa/QaController.java` | 追溯矩阵 + 用例生成端点 |
| 修改 | `evotrace-ui/QADashboardView.vue` | 计划编排增强 |

## 3. 方向三：质量门禁配置化（对标 SonarQube）

### 3.1 现状分析

- [QualityGateChecker.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/quality/QualityGateChecker.java) 有 5 项硬编码检查（权重固定：30/25/20/15/10）。
- 局限：检查项、阈值、权重全部硬编码，无法配置；缺少复杂度/重复度维度。

### 3.2 借鉴设计方案

**(a) 规则可配置化**
- 新增 `quality_gate_rule` 表：`id, project_id, rule_key, enabled, threshold, weight, params(jsonb)`。
- 新增 `QualityGateRule` 实体 + `QualityGateRuleService` + Controller。
- `QualityGateChecker.check()` 改为遍历启用的规则，逐条执行，支持自定义权重。
- 默认规则迁移：5 项硬编码改写为种子数据。

**(b) 新增检查维度**
- 借鉴 ArchUnit / SonarQube：复杂度、重复代码、架构层级违规（可选，依赖 Neu4j 或静态分析数据）。
- 预留 `params` 扩展点，不阻塞主流程。

### 3.3 改动清单

| 类型 | 文件/模块 | 改动 |
|------|----------|------|
| 新增 | 数据库 migration | `quality_gate_rule` 表 + 种子规则 |
| 新增 | `server/quality/QualityGateRule.java` + `QualityGateRuleService.java` + `QualityGateRuleController.java` | 规则 CRUD |
| 修改 | `server/quality/QualityGateChecker.java` | 改为可配置规则驱动 |
| 修改 | `evotrace-ui/**` | 门禁配置页面 |

## 4. 方向四：需求/迭代增强（对标禅道）

### 4.1 现状分析

- [RequirementService.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/requirement/RequirementService.java) 已有状态机 + `requirement_status_history` 审计表 + E2E trace。

### 4.2 借鉴设计方案

**(a) 需求状态变更时间线 UI**
- 新增接口 `GET /pm/requirements/{id}/status-history`。

- 燃尽图：基于迭代开始/结束 + 任务数，用 ECharts 绘制（`requirement_task` 已有 status=DONE 数据）。

## 5. 通用增强（横切）

### 5.1 多模型路由（Ollama / LangChain4j 借鉴）
- [ModelRouter.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/ai/ModelRouter.java#L138-L140) 的 `clientFor(taskType)` 目前统一返回 `activeClient`，可扩展为按 taskType 路由（摘要用便宜模型、审查用高质量模型），并支持 Ollama 本地模型（`baseUrl=http://localhost:11434/v1`）。

### 5.2 Prompt 模板引擎
- [PromptLoader.java](file:///Users/sheeran/gee/evotrace/evotrace-server/src/main/java/io/evotrace/server/ai/PromptLoader.java) 目前仅支持 `{key}` 替换。可借鉴 LangChain4j 支持 `{{#if}}` / `{{#each}}` 条件渲染，需引入 Mustache 依赖。

## 6. 实施优先级建议

| 优先级 | 方向 | 独立交付 | 风险 |
|--------|------|---------|------|
| P0 | 方向三：质量门禁配置化 | 高（纯新增，不破坏现有） | 低 |
| P0 | 方向四：需求状态时间线 UI | 高（纯前端+1接口） | 低 |
| P1 | 方向一：单 MR 描述生成 + 审查回写 | 中（新增服务） | 中 |
| P1 | 方向二：AI 用例生成 | 中（复用 ModelRouter） | 中 |
| P2 | 方向二：测试计划编排 | 中（前端） | 中 |
| P2 | 通用：多模型路由 / Prompt 引擎 | 低（较大改造） | 高 |
