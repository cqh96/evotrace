## 1. 设计原则

1. **约定式主键**：绝大多数表使用 `BIGINT GENERATED ALWAYS AS IDENTITY` 自增主键；业务唯一键（`project_key`、`event_id`、`api_key` 等）另建 `UNIQUE` 约束。
2. **多租户隔离**：`workspace` 为顶层隔离单元，`project` 归属 workspace；控制台查询绝大多数以 `project_id` 维度过滤。
3. **事件按时间分区**：`change_event` 为 `RANGE(occurred_at)` 分区表的父表，按月建分区，避免事件表无限膨胀。
4. **结构优先、JSON 兜底**：结构化字段落列，灵活/可扩展信息（边元数据、审计明细、快照内容）用 `JSONB`。
5. **软硬结合**：`artifact_link.status` 用于边状态机（ACTIVE/PENDING/REJECTED/IGNORED）；破坏/删除通常物理删 + 审计。
6. **时间默认值统一**：`created_at`/`updated_at` 均为 `TIMESTAMPTZ NOT NULL DEFAULT now()`，`updated_at` 由应用层负责刷新。

## 3. 各域表结构

### 3.1 核心变更域

#### `workspace`（工作空间）
| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT IDENTITY PK | |
| name | VARCHAR(128) | 工作空间名 |
| plan | VARCHAR(32) DEFAULT 'community' | 套餐 |
| ai_privacy_default | VARCHAR(32) DEFAULT 'STRUCTURE_ONLY' | AI 隐私默认级别 |
| created_at / updated_at | TIMESTAMPTZ | |

#### `project`（项目）
| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT IDENTITY PK | |
| workspace_id | BIGINT → workspace | 所属空间 |
| project_key | VARCHAR(64) | 业务键，`UNIQUE(workspace_id, project_key)` |
| name | VARCHAR(128) | 项目名 |
| repo_url | VARCHAR(512) | 仓库地址 |
| default_branch | VARCHAR(128) DEFAULT 'main' | |
| privacy_level | VARCHAR(32) DEFAULT 'STRUCTURE_ONLY' | |
| status | VARCHAR(16) DEFAULT 'ACTIVE' | |

#### `application`（应用）
| 列 | 说明 |
| --- | --- |
| project_id | → project |
| app_key | `UNIQUE(project_id, app_key)` |
| name / tech_stack / owner | |

#### `api_credential`（接入凭证）
| 列 | 说明 |
| --- | --- |
| api_key | `UNIQUE`，对外呈现 |
| secret_hash | 仅存哈希，不存明文 |
| scope | DEFAULT 'INGEST' |
| status | ACTIVE / REVOKED 等 |
| expires_at | 过期时间 |

#### `iteration`（迭代）
`UNIQUE(project_id, source, external_key)`，字段：external_key、title、source、status、url、synced_at。

#### `change_event`（变更事件，按月 RANGE 分区父表）
| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT IDENTITY | 分区表无主键单列，主键 `(id, occurred_at)` |
| project_id | BIGINT | |
| app_id | BIGINT | |
| event_id | VARCHAR(64) | 事件唯一 id |
| idempotency_key | VARCHAR(256) | 幂等键，`UNIQUE(idempotency_key, occurred_at)` |
| event_type | VARCHAR(32) | CODE_COMMIT / MR_MERGED / TAG / DDL / CONFIG 等 |
| branch | VARCHAR(255) | |
| commit_sha | VARCHAR(64) | |
| author | VARCHAR(128) | |
| iteration_id | BIGINT | 旧迭代归属 |
| commit_message | VARCHAR(2048) | 由 V6 提供，commit/MR 消息（Trace 治理、悬空键检测数据源） |
| blob_ref | VARCHAR(512) | diff 大对象引用 |
| summary_status | VARCHAR(16) DEFAULT 'PENDING' | AI 摘要状态 |
| occurred_at | TIMESTAMPTZ | 分区键 |

分区：`change_event_2026_07 PARTITION ... FOR VALUES FROM ('2026-07-01') TO ('2026-08-01')`；`V7__partitions.sql` 动态按月建分区。
索引：`idx_change_event_timeline(project_id, occurred_at DESC)`、`idx_change_event_commit(project_id, commit_sha)`。

#### `change_file`（文件级 diff）
字段：event_id、file_path、old_path、change_kind、add_lines、del_lines、diff_blob_ref；索引 `file_path`。

#### `release`（版本）
| 列 | 说明 |
| --- | --- |
| project_id / app_id | `UNIQUE(project_id, app_id, version)` —— 同一项目内不同应用可有相同 version |
| version | 版本号 |
| base_commit / tag / env / status / released_at | |

> Trace 版本全景一律以 `release.id` 定位（跨 app 版本歧义消除），见 [10-链路增强与补齐方案](10-链路增强与补齐方案.md) §8.4.5（P0-3）。

#### `snapshot` / `snapshot_item` / `snapshot_item_ref`（快照）
- `snapshot`：release_id、app_id、type(FULL/DELTA)、baseline_id、item_count、status。
- `snapshot_item`：`content_hash` PK（内容寻址）、category、identity_key、content_json。
- `snapshot_item_ref`：`(snapshot_id, item_hash)` PK、change_flag(ADDED/REMOVED/UNCHANGED)。

### 3.2 分析域

- `api_dependency_graph`：caller、callee、call_type → 影响面 BFS。
- `breaking_change_alert`：change_type、severity(CRITICAL/WARNING/INFO)、detail JSONB、acknowledged。
- `release_risk_score`：release_id、total_score、sub_scores、explanation。

### 3.3 PM-QA 域

#### `requirement`（需求）
| 列 | 说明 |
| --- | --- |
| project_id / workspace_id | |
| title / priority / status / source / pm / assigned_to | |
| prototype_url / design_url / business_value / user_story / acceptance_criteria / estimate_days | |
| target_version | 目标版本 |
| iteration_id | 旧归属 |
| req_key | `VARCHAR(64)`，Trace 业务键；`uk_requirement_project_req_key(project_id, req_key) WHERE req_key IS NOT NULL`；索引 `idx_requirement_req_key(project_id, lower(req_key))` |
| external_key | 外部系统键 |
| created_at / updated_at | |

#### `test_case` / `test_execution` / `test_plan` / `test_plan_item`
- `test_case`：title、test_type、priority、steps、related_files、related_apis、requirement_id、parent_id、node_type。
- `test_execution`：test_case_id、plan_item_id、status、executor、result_detail、release_id、executed_at。
- `test_plan`：name、target_version、from_version、status。
- `test_plan_item`：test_plan_id、test_case_id、sort_order、status、executor、result_detail。

#### `bug_ticket` / `bug_change_link`
- `bug_ticket`：title、severity(P0-P3)、status、found_by、found_version、fixed_version、assigned_to、requirement_id、external_key。
- `bug_change_link`：bug_id ↔ change_event_id、link_type(INTRODUCE/FIX)。

#### `quality_gate` / `quality_gate_rule`
- `quality_gate`：release_id、status(PASSED/FAILED)、score、check_results JSONB、checked_by、checked_at。
- `quality_gate_rule`：可配置检查项阈值（对标 V11）。

#### `e2e_trace`（端到端追溯物化）
字段：project_id、requirement_id、bug_id、release_id、trace_path JSONB。Trace Phase A 通过 `POST /trace/rebuild` 刷新。

#### `pm_qa_notification`
通知记录：target_user、role、type、content、is_read。

### 3.4 订阅域
- `subscription_rule`：name、workspace_id、user_id、filter JSONB、channel、webhook_url、enabled。
- `notification_log`：channel、title、content、status、error_msg。

### 3.5 代码审查域
- `ai_code_review`：项目/事件/审查状态/摘要。
- `review_finding`：review_id、severity、file、line、message。
- `ai_commit_stats`：提交统计。

### 3.6 测试平台域（V15/V16）
`test_case_version`、`api_scenario`、`api_scenario_step`(config JSONB)、`test_report`(share_token)、`test_schedule`(cron)、`performance_test`(summary JSONB)、`ci_trigger`、`ui_test_case`(steps JSONB)。

### 3.7 接口调试域（V14）
`api_endpoint`(params JSONB、request_body、response_schema、mock_response、source)、`api_environment`(headers JSONB)、`api_test_case`(request/response JSONB)。

### 3.8 外部同步域
`project_feishu_config`：app_id、app_token、bug_table_id、case_table_id、field_map JSONB、status_map JSONB、enabled。

### 3.9 链路增强域（Trace Core，V18/V19）

#### `project_trace_setting`（协作约定）
| 列 | 默认 | 说明 |
| --- | --- | --- |
| project_id | — | PK → project |
| req_key_prefix | 'REQ' | 业务键前缀 |
| auto_link_enabled | TRUE | 自动建边开关 |
| hash_issue_enabled | FALSE | `#123` → 需求映射 |
| branch_template | 'feature/{reqKey}-*' | |
| commit_template | '{reqKey} <summary>' | |
| ai_suggest_enabled | FALSE | |

#### `project_link_rule`（关联规则）
| 列 | 说明 |
| --- | --- |
| name / enabled / priority | 越小越先匹配 |
| pattern | 正则，含命名组 `(?<reqKey>…)` |
| extract_group | DEFAULT 'reqKey' |
| apply_to | COMMIT_MESSAGE / MR_TITLE / MR_BODY / BRANCH_NAME |
| link_type | DEFAULT 'IMPLEMENTS' |
| confidence | 0-100 |

默认种子（V18 写入，V19 将 REQ 正则 `\d{3,}` 修正为 `\d+`）：
| name | pattern | apply_to | confidence |
| --- | --- | --- | --- |
| REQ key | `(?i)\b(?<reqKey>REQ[-_]?\d+)\b` | COMMIT_MESSAGE/MR_TITLE/BRANCH_NAME | 95 |
| JIRA/Issue key | `(?i)\b(?<reqKey>[A-Z][A-Z0-9]+-\d+)\b` | COMMIT_MESSAGE/MR_TITLE | 90 |
| Hash issue | `#(?<reqKey>\d+)\b` | COMMIT_MESSAGE | 70（默认关闭） |

#### `artifact_link`（核心边表）
| 列 | 说明 |
| --- | --- |
| from_type / from_id / to_type / to_id | 工件标识，统一字符串 |
| link_type | IMPLEMENTS / BELONGS_TO / COVERS / TESTS / INTRODUCES / FIXES / BLOCKS / GATES / SHIPPED_IN / DEPLOYED_AS / DERIVED_FROM |
| confidence | 0-100 |
| source | AUTO_COMMIT_KEY / AUTO_MR / AUTO_BRANCH / AUTO_AI / AUTO_TIME_WINDOW / MANUAL / IMPORT / MIGRATION |
| status | ACTIVE / PENDING / REJECTED / IGNORED |
| created_by / meta | meta JSONB（matchedText、applyTo、eventId 等） |

索引：`uk_artifact_link_active(project_id, from_type, from_id, to_type, to_id, link_type) WHERE status='ACTIVE'`（活跃边防重复）、`idx_artifact_link_from`、`idx_artifact_link_to`、`idx_artifact_link_status(project_id, status, confidence)`。

置信度策略：≥85 → ACTIVE；60–84 → PENDING；<60 → 不写或 PENDING。

#### `trace_link_audit`（审计）
action：CREATE / CONFIRM / REJECT / IGNORE / DELETE / REBUILD；detail JSONB；索引 `(project_id, created_at DESC)`。

#### `trace_orphan_ignore`（未关联提交忽略）
`UNIQUE(project_id, change_event_id)`，字段：reason、actor、created_at。

### 3.10 DevOps 治理域（V17）
`automation_rule`(trigger_event、action、condition JSONB、config JSONB、enabled、run_count)、`automation_rule_log`、`project_member`(user_id、role)、`feedback`(source、content、ai_analysis、converted_*)、`dev_metric`(period、payload JSONB)。

### 3.11 IAM 域
`sys_user`：username、password_hash、display_name、role、status。

### 3.12 AI 域
- `ai_semantic_unit`：target_type/target_id、kind(SUMMARY/RELEASE_NOTE/IMPACT/QA)、content、model、confidence、confirmed_by。
- `ai_embedding`：target_type/target_id、model、`embedding vector(1024)`、`UNIQUE(target_type, target_id)`。
- `ai_usage`：workspace_id、model、task_type、prompt_tokens、completion_tokens、cost。
- `ai_model_config`：name、provider、base_url、api_key(脱敏)、model_name、temperature、enabled、is_default。

### 3.13 审计域
`audit_log`：actor、action、target、detail JSONB、created_at（所有敏感操作记录）。

## 4. 关键索引与约束

| 目的 | 索引/约束 |
| --- | --- |
| 事件时间线 | `change_event(project_id, occurred_at DESC)` |
| 事件幂等 | `change_event UNIQUE(idempotency_key, occurred_at)` |
| 需求业务键唯一 | `requirement(project_id, req_key) WHERE req_key IS NOT NULL` |
| 活跃边唯一 | `artifact_link(project_id, from_type, from_id, to_type, to_id, link_type) WHERE status='ACTIVE'` |
| 边查询 | `artifact_link(project_id, from_type, from_id, link_type)` / `(project_id, to_type, to_id, link_type)` |
| 规则匹配 | `project_link_rule(project_id, enabled, priority)` |
| 快照内容寻址 | `snapshot_item(content_hash)` PK |
| 向量检索 | `ai_embedding` pgvector 索引（1024 维） |

---

## 5. 分区与保留策略

- `change_event` 按月 `RANGE(occurred_at)` 分区，`PartitionMaintainer` 动态创建分区。
- 保留策略按项目配置；快照内容寻址去重（`content_hash`），`change_event` 走分区裁剪。
