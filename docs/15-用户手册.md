## 1. 系统简介

EvoTrace 是一个**覆盖软件全生命周期的演化追踪与智能分析平台**，打通「需求 → 代码 → 测试 → 缺陷 → 发布」全链路，借助 AI 把海量变更信息转译为业务语义。

本文档面向平台使用者，按角色与功能模块介绍操作流程。技术接入与部署请参阅 05/06/04 文档。

## 2. 登录与工作台

### 2.1 登录

- 访问地址：`http://<host>:5173`（开发）或生产域名。
- 默认账号：`admin` / `admin123`（**生产环境请立即修改**）。
- 登录成功后进入 **项目总览** 页面。

### 2.2 项目切换

系统按项目（project）隔离数据。在顶部切换到目标项目后，所有页面均基于该项目展示。切换项目会加载对应项目的 API 凭证、需求、变更、链路等数据。

### 2.3 个人工作台（`/workbench`）

聚合当前用户：我的需求、我的缺陷、我的任务、反馈等，是个人待办的统一入口。

## 3. 项目管理员（Admin）

### 3.1 接入管理（`/integration`）

管理项目、应用与 API 凭证：

1. 创建项目后系统自动生成一套 API Credential（`api_key` + `secret`）。
2. **记录并妥善保存** secret —— 仅创建/轮换时可见，后续用于 SDK、CLI、Webhook 签名。
3. 支持凭证轮换（`rotate`）与吊销（`revoke`）。

### 3.2 项目成员与角色（`/members`）

| 角色 | 说明 |
| --- | --- |
| ADMIN | 项目管理员，拥有全部权限 |
| PM | 需求、缺陷、门禁、度量 |
| DEVELOPER | 时间线、审查、智能分析 |
| QA | 测试用例、测试报告、缺陷 |
| OPS | 版本、门禁、度量、自动化规则 |

添加/移除成员、调整角色均在 `/members` 完成。

### 3.3 AI 模型配置（`/model-config`）

配置多模型路由（文本/图像/视频模型），为 AI 问答、摘要、用例生成提供模型。API Key 仅展示脱敏值。

### 3.4 自动化规则（`/automation`）

配置「事件触发动作」规则，例如：DDL 变更 + 匹配文件 → 推送飞书通知。满足条件时自动执行动作。

## 4. 研发（Dev）

### 4.1 演化时间线（`/timeline`）

按时间查看项目全部变更事件（commit / MR / 发布），支持文件历史追溯与 AI 变更摘要。

### 4.2 版本对比（`/compare`)

选择 fromVersion / toVersion，生成 5 维度对比报告（代码、依赖、破坏性变更、风险、发布说明）。

### 4.3 代码审查（`/code-review`）

- 生成 PR/MR 描述与代码审查意见。
- 审查结果可回写 Git（MR 描述/评论）。

### 4.4 智能分析（`/analysis`）

聚合代码热点、破坏性变更检测、风险评分，辅助判断变更影响面。

### 4.5 AI 演化问答（`/qa`）

基于项目演化数据提问，例如「最近 payment 模块有哪些破坏性变更？」，返回带引用的回答。

### 4.6 变更订阅（`/subscriptions`）

按项目 / 事件类型 / 文件 glob / 应用设置订阅规则，触发时推送飞书等通知。

## 5. 产品（PM）

### 5.1 需求看板（`/pm`）

看板流转（PROPOSED → TESTING → ...）+ 质量门禁。卡片展示优先级、**需求键（reqKey）**、目标版本、预估人天与**完整度小环**。

### 5.2 需求全景（需求详情抽屉 → 「全景」Tab）

任一需求可打开「全景」查看：

- **完整度**：依据代码/测试/缺陷/版本关联打分，展示各项检查通过状态。
- **链路路径**：需求 → 代码 → 测试 → 缺陷 → 发布 的 Trace 路径。
- **关联**：代码、测试用例、缺陷、版本等关联信息。

### 5.3 缺陷管理（`/bugs`）

缺陷状态流转 + 看板 + 追溯，可关联到需求与最近变更。

### 5.4 反馈管理（`/feedback`）

收集反馈，AI 辅助将反馈转为需求或缺陷。

### 5.5 研效度量（`/metrics`）

交付率、缺陷逃逸率、吞吐、周期等研发效能指标。

### 5.6 版本全景（`/release-cockpit`）

选择版本后查看：

- **就绪度**：质量门禁结果、完整度评分。
- **变更集**：版本关联的需求、变更（已关联/未关联）、缺陷（P0/P1）、测试摘要。
- **重建变更集**：手动重建该版本的变更集。

## 7. 链路治理（Trace Core / Phase A）

> 面向 PM / QA / Ops，用于维护「需求 ↔ 代码」等关联，让全链路可追溯。

### 7.1 链路治理中心（`/trace-governance`）

概览卡片展示四类待办数量，点击卡片或 Tab 进入明细：

| Tab | 说明 | 操作 |
| --- | --- | --- |
| **未关联提交** | 未命中任何需求键的 commit | 手动关联 / 忽略（记录原因） |
| **待确认边** | 规则自动识别的低置信度关联，需人工确认 | 确认 / 驳回 |
| **悬空键** | 提交中引用了系统中不存在/未创建的需求键 | 一键创建需求并回链 |
| **断链检测** | 需求缺代码 / 缺口例 / 有阻塞缺陷 / 版本缺门禁 | 跳转补齐 |

**设置与规则**（右上角按钮）：

- **链路设置**：`reqKeyPrefix`（需求键前缀）、`autoLinkEnabled`（自动关联开关）、`hashIssueEnabled`、`aiSuggestEnabled`。
- **关联规则**：定义从 commit message / MR 标题 / 分支提取需求键的正则，命中后自动创建 `IMPLEMENTS` 等关联边。支持恢复默认种子规则。

### 7.2 需求键（req_key）

- 需求键格式：`<前缀>-<数字>`，如 `REQ-5`。
- 在 commit message、MR 标题或分支名中书写需求键，即可被规则识别并自动建立关联。
- 需求看板卡片与需求全景均展示 req_key。

## 8. 常见问题（FAQ）

| 问题 | 说明 |
| --- | --- |
| 提交无法自动关联需求？ | ① 确认项目「链路设置」已开启自动关联；② 确认 commit message 中需求键格式与规则匹配；③ 到治理中心「悬空键」检查是否引用了未创建的需求键。 |
| 需求全景显示不完整？ | 完整度取决于需求与代码/用例/缺陷/版本的关联情况，逐个补齐关联后刷新。 |
| 版本全景无数据？ | 确认该版本已有关联需求；可点击「重建变更集」重新聚合。 |
| secret 丢失？ | 到接入管理执行凭证轮换（rotate），旧凭证立即失效。 |
| 忘记密码？ | 联系管理员重置 `sys_user` 密码。 |
| 如何接入新项目代码？ | 见 05-开发者接入指南.md（Java SDK / CLI / Webhook）。 |
